## Color system, typography, and design tokens

Every convention here is enforced or recorded by `scripts/color-audit/audit.py` (exits 1 on any P0; waived rows in a separate `waived` section), `scripts/color-audit/solve.py` (proposes passing values, hue held, lightness walked), and `scripts/verify/phase17_tokens.py`. History and rationale: `docs/color-audit-2026-08.md`. Read this file before touching anything in `dabarat/static/css/` or a color in `palette.js`.

### Themes and pigments

- 8 themes: 4 dark (Ink, Mocha, Rosé Pine, Tokyo Storm) + 4 light (Vellum, Latte, Rosé Pine Dawn, Tokyo Light). Ink + Vellum are The Scholar's Codex pair — parchment-and-iron-gall register with tungsten gold and rubricated red-ochre signature accents. The pigments have fixed jobs (2026-09-06): the home title (`--home-title`: tungsten on Ink, iron-gall on Vellum) and the single h3 rubric (`--h3-color`: ochre on Ink, cinnabar on Vellum, the same pigment as its inline code); functional marks — selection, TOC current section, row hover — stay blue like every other theme.
- **Light-theme override convention**: All four light themes (Latte, Vellum, Rosé Pine Dawn, Tokyo Light) MUST appear together in every `[data-theme="..."]` override block across all CSS files (`editor.css`, `annotations.css`, `base-layout.css`, etc.). Omitting any light theme from a selector group causes silent contrast/styling regressions on that theme.
- **Vellum shadow exception**: Vellum uses warm umber shadows (`rgba(70, 48, 20, ...)`) instead of the neutral `rgba(0, 0, 0, ...)` used by every other theme. Pure-black shadows punch cold holes into its warm parchment base; the convention break is documented inline in `theme-variables.css` and should not be "normalized" back.

### Color rules

- **Color convention**: Never use hardcoded rgba channel values—use `rgba(var(--ctp-*-rgb), alpha)` from `theme-variables.css`. RGB companions (`--ctp-yellow-rgb`, `--ctp-blue-rgb`, etc.) auto-switch per theme. Latte overrides only needed when alpha values differ from Mocha defaults. TAG_COLORS in `palette.js` uses the `--badge-<hue>-fg` role tokens for text and CSS variable references for washes. Shadows are the one sanctioned neutral: `--elevation-1`/`--elevation-2` in `theme-variables.css` own every `rgba(0,0,0,…)`; modules consume the tokens (tinted accent glows stay `rgba(var(--ctp-*-rgb), α)`). `audit.py` (`hardcoded_rgba_findings`, `undefined_var_findings`) and `scripts/verify/phase17_tokens.py` fail on hex/named colors and non-neutral rgba literals outside `theme-variables.css` and on any `var(--x)` that doesn't resolve in every theme; neutral washes (`rgba(0,0,0|255,255,255|128,128,128, α)`) stay allowed as borders/washes, and only neutral *box-shadows* are policed (phase17 V1). Theme swatches (`themeSwatches()` in `palette.js`) and surface probes (`_themeVar`/`_themeSurfaceRgb` in `theme.js`) are read from computed style — there is no hand-copied palette table to keep in sync.
- **Whisper tier (contrast waiver)**: document-view `--ctp-overlay1` text (figcaptions, footnote backrefs, list markers) and the TOC section kicker (`--ctp-overlay0` on mantle) are deliberately de-emphasized and waived from WCAG AA by decision — do not "fix" it to 4.5:1. On the home screen the waiver covers ONLY hover-revealed ghost controls (`.home-card-remove`, `.ws-section-remove`, `.ws-entry-remove`, `.home-section-remove`, `.home-quote-refresh`); all other home text passes 4.5:1 via the home role tokens ("everything readable" decision, 2026-08-19). `scripts/color-audit/audit.py` tracks waived rows in a separate `waived` section; everything else must pass its tier, and the script exits 1 on any P0.
- **Color-role tokens**: Elements whose raw accent can fail contrast on its real surface consume role tokens, not accents: `--code-fg`/`--code-bg` (inline code — surface0 on dark themes; on the four light themes a rose wash `rgba(maroon|red, .08–.09)` over base with a solved rose-maroon ink, audited on base; Vellum uses its cinnabar rubric — never put the cold surface0 slab back under light-theme code), `--hljs-*` (syntax, on mantle), `--tpl-pill-mustache`/`--tpl-pill-dollar` (over their washes), `--h3/h4/h5-color` (on base), `--link-visited`, `--stat-add`/`--stat-del`, `--external-badge-fg` (on **crust**, its real surface), `--toc-link` (on mantle), the home tokens `--home-meta`/`--home-control`/`--home-icon`/`--home-title` (the home h1: lavender by default, tungsten on Ink, iron-gall on Vellum — large text, 3:1 on the wash) (base + card + **crust** — the status bar consumes them too, "status bar readable" decision 2026-09-06 — and the **home wash**: `.home-screen` paints two accent radial washes over base, blue .07 at the top-left and mauve .05 at the bottom-right, so white cards no longer sit on a bare grey slab in Latte/Tokyo Light; text directly on the ground is audited on `[BASE, blue .07]` via the `(wash)` rows, Rosé Pine re-solved there; light-theme `.home-card` hairlines are `rgba(blue, .16)` to echo it), and `--badge-<hue>-fg` (badge/tag text over its wash on card, base, and surface0 — the worst surface wins). h3–h5 audit at 4.5:1 (they render below the 18.66px large-text bar at every allowed `--base-size`); only h1/h2 get 3:1. Ink and Vellum keep h3 as the single rubric accent and set `--h4-color`/`--h5-color` to `--ctp-text` (tonal tiers, structure through weight/small-caps — a `/* pair-scoped */` comment marks those Ink+Vellum-only groups so `override_findings` skips them). Defaults alias the accents in `:root`; themes override only failing slots with concrete hexes in `theme-variables.css` — mocha's own overrides live in a standalone `[data-theme="mocha"]` block right after `:root` (concrete values in `:root` would leak into every theme). New color+surface pairs must be registered in `USED_PAIRS` in `audit.py`; `scripts/color-audit/solve.py` proposes passing values (hue held, lightness walked) for any row that fails. For a token used on two surfaces, adopt the worse-surface solution (card for dark themes, base for light).
- **Interactive token convention**: For hover/focus states on surfaces that use `--card-bg` (white in light themes), use `var(--interactive-hover-bg)` (dark: `--ctp-surface1`, light: `--ctp-crust`) and `var(--interactive-muted-bg)` (dark: `rgba(surface1, 0.85)`, light: `rgba(0,0,0,0.06)`) instead of raw `var(--ctp-surface1)` which is invisible on white.
- **Attention-hue convention**: yellow marks pending user work (unsaved/dirty state — caret, badge); peach marks provenance/awareness (external-change badge, unseen-activity dots). The split is deliberate severity semantics, not drift — don't unify them.

### Design tokens and shared recipes

- **Design tokens** (`theme-variables.css` `:root`, guarded by `scripts/verify/phase17_tokens.py`): `--radius-xs/sm/md/lg/xl/2xl/pill`, `--z-toc/panel/float/status/menu/banner/palette/modal/lightbox/overlay`, `--dur-fast/base/mid/slow/slower`, `--ease-standard/out-back/out-expo`, `--elevation-1/2`, `--font-sans/serif/mono`, `--measure` (900px prose column shared by read/edit/frontmatter/variables). Modules never write a px radius, a z-index ≥ 10, a `transition` with a literal duration or `all`, or a neutral rgba shadow; local stacking z-indexes 0–5 are fine. `.btn` in `base-layout.css` is the secondary-pill recipe (DM Sans 11px, `--home-control`, `--ctp-surface1` border, `--interactive-muted-bg` hover, blue `:focus-visible` ring, `scale(.96)` active, `:disabled` at .55) — `.home-action-btn`, `.ws-btn`, `.home-open-btn`, `.version-btn`, instance-row buttons, banner buttons, and the editor Save/Discard pair are deltas on it (history-ui's border-only hover rationale survives as a delta rule). `accent-color: var(--ctp-blue)` and `scrollbar-color` per mode sit on `:root`.

### Surfaces with settled designs

- **Tab bar**: dark themes are a depth ladder — bar on crust, inactive tabs on `--toc-bg` (mantle at the opacity alpha), hover surface0, active on base — with no accent rule (a blue top rule on the active tab was tried and rejected, 2026-09-06). Light themes paint the home-ground blue wash (`rgba(blue, .06)` over `--body-bg`, layered in CSS because `applyOpacity()` writes `--crust-bg` inline), transparent tabs with the `rgba(blue, .16)` card hairline as divider, and the active tab lifted on base; the add-file field sits on `--card-bg`, never surface0. Tab text is `--home-control`, audited on mantle (dark) and on the wash (light) by the `tab` rows in `audit.py`.
- **Editor toolbar** (2026-09-06): sits on `--toc-bg` (mantle at the opacity alpha), never crust. Formatting buttons (`.edit-fmt-btn`) are 32px with one neutral hover wash (`--interactive-muted-bg`) and one blue wash when toggled on (`rgba(blue, .12)`, `.18` on hover) — no glow, ring, or inset indicator. Groups sit 12px apart (`.edit-toolbar-sep` hairline with 6px margins). The "Editing" badge is neutral (`--home-control` on an overlay1 wash) until `body.edit-dirty`, when it and the tab-bar rule turn yellow — pending work, per the attention-hue convention; edit mode itself is not an alert. Save and Close use outline hover (accent border + text, no fill); the dirty Save on light themes uses `--ctp-text` instead of `--ctp-yellow`. Audit rows: `editor fmt button`, `editor status`, `edit-mode badge (clean|dirty)` on mantle.
- **Blockquotes** are quotations, not callouts (2026-09-06): upright body ink, one 2px `--ctp-surface1` rule, no fill, no radius, no blanket italic — so authored `em` inside a quote stays italic and the old `blockquote em, blockquote code { font-style: normal }` workaround is gone. `--blockquote-color` defaults to `--ctp-text`; only Ink (faded vellum) and Vellum (sepia) tint it. `--blockquote-bg` no longer exists — filled, colored containers are for explicit callouts, not `>`.
- **Tables** (2026-09-06): editorial by default — authored header casing (no `text-transform`), neutral 600 `--ctp-text` headers on mantle (opaque, so the sticky `thead` covers rows), horizontal rules only (`th` surface1, `td` surface0). `render.js` adds `table.dense` past 8 body rows or 5 columns; only dense tables get the cell grid, `--row-even-bg` zebra, and `--row-hover-bg` hover. Don't put the grid back on small tables.

### Typography

- **Typography parity**: prose rules in `typography.css` are global (`h1`…`h6`, `p`, `pre code`, `table`), so `.ProseMirror` inherits them and `editor.css` carries only editor chrome — never restate a heading color/size there (phase17 V9). Scale is em-based off `--base-size` (`pre code` 0.82em, `table` 0.88em, footnotes 0.875em); `hr` is a 40% centered `--ctp-surface1` rule; `text-wrap: balance` on display headings, `pretty` on paragraphs, `tabular-nums` on stats/dates. Hebrew webfonts load on demand — `ensureHebrewFonts(md)` in `render.js` injects the `<link id="dabarat-hebrew-fonts">` on the first `/[\u0590-\u05FF]/` match and `init.js` awaits `document.fonts.load` before the export sentinel.
- **Footnotes**: `marked-footnote@1.4.0` UMD loaded after marked.js, registered via `marked.use(markedFootnote())` in `render.js`. Styles in `typography.css` (`section.footnotes`). Editor save path in `editor.js` post-processes serialized markdown to unescape `\[^...\]` → `[^...]` since tiptap-markdown doesn't understand footnote syntax.
